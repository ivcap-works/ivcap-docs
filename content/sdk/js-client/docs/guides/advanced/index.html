    Advanced Usage¶

    This guide covers less common but important patterns: token rotation, low-level HTTP access, browser integration, and working with queues and secrets.

    Token Rotation¶

    For long-running processes (background workers, agents, servers), your JWT token may expire while the client is running. Rotate it without restarting:

    import { IvcapClient } from "@ivcap/client";

const client = new IvcapClient({
  baseUrl: "https://develop.ivcap.net",
  token: await getInitialToken(),
});

// Rotate every 55 minutes (before the 1-hour expiry)
setInterval(async () => {
  const newToken = await myTokenProvider.refresh();
  client.setToken(newToken);
  console.log("Token rotated at", new Date().toISOString());
}, 55 * 60 * 1_000);

    Low-level HTTP Access¶

    For endpoints not yet covered by the SDK, access the underlying Axios instance directly:

    const axios = client.getHttpClient().getAxios();

// Custom GET request
const response = await axios.get("/1/some/custom/endpoint");
console.log(response.data);

// POST with a custom body
await axios.post("/1/custom/resource", { myField: "value" });

    Note

    Prefer the typed resource methods (client.artifacts, client.jobs, …) whenever they cover your use case. Fall back to the raw Axios instance only for non-standard or experimental endpoints.

    Custom Request Headers¶

    Pass custom headers to every request via the config:

    const client = new IvcapClient({
  baseUrl: "https://develop.ivcap.net",
  token:   process.env.IVCAP_JWT,
  headers: {
    "X-Trace-Id":  "my-trace-12345",
    "X-Client-Id": "my-service",
  },
});

    Request Timeout¶

    The default timeout is 30 seconds. Override it globally:

    const client = new IvcapClient({
  baseUrl: "https://develop.ivcap.net",
  token:   process.env.IVCAP_JWT,
  timeout: 60_000,  // 60 seconds
});

    Working with Queues¶

    Queues allow services and external systems to communicate asynchronously.

    // Create a queue
const queue = await client.queues.create({
  name:        "results-queue",
  description: "Receives job completion events",
});

// Publish a message
await client.queues.enqueue(queue.id, {
  schema:  "urn:example:schema:event:job-done:1",
  content: { jobId: "urn:ivcap:job:...", status: "succeeded" },
});

// Consume messages in a loop
while (true) {
  const msg = await client.queues.dequeue(queue.id);
  if (msg === null) break; // queue is empty

  console.log(msg.schema, msg.content);
}

// Clean up
await client.queues.delete(queue.id);

    Working with Secrets¶

    Store credentials securely on the platform:

    // Store a secret
await client.secrets.set({
  secretName:  "MY_API_KEY",
  secretValue: "super-secret-value",
  expiryTime:  Math.floor(Date.now() / 1000) + 86_400, // 24h from now (Unix seconds)
});

// List secrets (names + expiry only — values are NOT returned)
const list = await client.secrets.list();
list.forEach(s => console.log(s.secretName, s.expiryTime));

// Retrieve a secret value
const secret = await client.secrets.get("MY_API_KEY");
console.log(secret.secretValue);

// Delete
await client.secrets.delete("MY_API_KEY");

    Working with Projects¶

    // List all projects
for await (const p of client.projects.list()) {
  console.log(p.urn, p.name, p.status);
}

// Get project details
const proj = await client.projects.get("urn:ivcap:project:abc...");
console.log(proj.properties);

// Create a new project
const newProj = await client.projects.create({
  name: "Fire Risk Analysis 2026",
  properties: { region: "Tasmania" },
});

    Browser / Vite / Next.js Usage¶

    The SDK ships both ESM and CJS builds with no Node-specific APIs in the core logic. Axios handles HTTP and works transparently in browser environments.

    // Works in Vite, Create React App, Next.js client components, etc.
import { IvcapClient } from "@ivcap/client";

const client = new IvcapClient({
  baseUrl: import.meta.env.VITE_IVCAP_URL,
  token:   import.meta.env.VITE_IVCAP_JWT,
});

    Don't expose tokens to browsers in production

    If you use the SDK in the browser, ensure tokens are obtained via your own backend (e.g., a Next.js API route) and not hard-coded in the frontend bundle.

    Using Multiple Clients¶

    Create separate instances for different deployments or service accounts:

    const devClient  = new IvcapClient({ baseUrl: "https://develop.ivcap.net",    token: devToken });
const prodClient = new IvcapClient({ baseUrl: "https://production.ivcap.net", token: prodToken });
