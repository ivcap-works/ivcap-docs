    Running Jobs¶

    A job is a single execution of an IVCAP service.

    No top-level /jobs endpoint

    IVCAP exposes jobs through two API layers the SDK stitches together automatically. See the architecture note in the API reference for details.

    Job Lifecycle¶

    stateDiagram-v2
    [*] --> scheduled : create()
    scheduled --> executing : execution starts
    executing --> succeeded : completed successfully
    executing --> failed : service logic error
    executing --> error : platform / infra error
    succeeded --> [*]
    failed --> [*]
    error --> [*]
    Status Meaning
    scheduled Accepted by the platform, queued for a worker
    executing Currently running
    succeeded Completed successfully — results available
    failed Service logic reported a failure
    error Platform-level error (infrastructure, timeout, …)

    Terminal states: succeeded, failed, error.

    Submitting a Job¶

    createAndWait() — Submit and Block Until Done¶

    The simplest path for synchronous workflows. Handles both immediate (HTTP 200) and async (HTTP 202) job creation transparently:

    import { IvcapClient, JobResource } from "@ivcap/client";

const client = new IvcapClient();

const job = await client.jobs.createAndWait(
  "urn:ivcap:service:abc-123",
  {
    parameters: JobResource.buildParameters({
      input:     "urn:ivcap:artifact:xyz...",
      threshold: "0.8",
    }),
    name: "My analysis run",
  },
  {
    pollInterval: 5_000,   // poll every 5 seconds (default: 3 000 ms)
    timeout:     300_000,  // throw TimeoutError after 5 min (default: 300 s)
    onUpdate: (j) => console.log("status:", j.status),
  },
);

if (job.status === "succeeded") {
  console.log("Products:", job.products?.items.length ?? 0);
  if (job.resultContent) {
    console.log("Result:", JSON.stringify(job.resultContent, null, 2));
  }
}

    create() — Submit and Return Immediately¶

    Use create() when you want to fire off a job and handle the sync/async branching yourself. It returns a discriminated union:

    const result = await client.jobs.create(serviceId, {
  parameters: [{ name: "input", value: artifactId }],
  name: "background-job",
});

if (result.synchronous) {
  // HTTP 200 — already done
  console.log("Completed inline:", result.job.status);
} else {
  // HTTP 202 — poll later
  console.log("Job ID:    ", result.jobId);
  console.log("Service ID:", result.serviceId);
  if (result.retryLater) {
    console.log(`Retry after: ${result.retryLater}s`);
  }

  // Poll to completion
  const done = await client.jobs.waitUntilDone(
    result.serviceId,
    result.jobId,
    { pollInterval: 5_000, timeout: 300_000 },
  );
  console.log("Final status:", done.status);
}

    Using buildParameters() Helper¶

    Instead of writing { name, value } pairs manually, use the static helper. It also accepts a plain Record<string, string> directly:

    import { JobResource } from "@ivcap/client";

// Helper — converts { key: value } → [{ name, value }, ...]
const params = JobResource.buildParameters({
  input:     "urn:ivcap:artifact:xyz...",
  threshold: "0.8",
  region:    "Tasmania-North",
});

// Or pass the plain object directly — both are equivalent:
const result = await client.jobs.create(serviceId, {
  parameters: { input: "urn:ivcap:artifact:xyz...", threshold: "0.8" },
  name: "quick-run",
});

    Fetching an Existing Job¶

    get() — Fetch by Job ID (with automatic bootstrap)¶

    You only need the job URN. The SDK automatically resolves the serviceId from the DataFabric if you don't provide it:

    // Bootstrap lookup — only job ID needed (one extra DataFabric round-trip)
const job = await client.jobs.get("urn:ivcap:job:xyz-456");

// Fast path — skip the DataFabric lookup when you already know the service
const job = await client.jobs.get("urn:ivcap:job:xyz-456", {
  serviceId: "urn:ivcap:service:abc-123",
});

console.log(job.status, job.startedAt, job.finishedAt);

    waitUntilDone() — Poll an Already-Submitted Job¶

    const done = await client.jobs.waitUntilDone(
  serviceId,  // required — use resolveServiceId() if unknown
  jobId,
  {
    pollInterval: 3_000,
    timeout:     600_000,
    onUpdate: (j) => console.log(`[${new Date().toISOString()}] ${j.status}`),
  },
);

    Listing Jobs¶

    list() queries the DataFabric and returns jobs across all services — no serviceId required:

    // Iterate the 20 most recent jobs
for await (const j of client.jobs.list({ limit: 20 })) {
  const svc = j.serviceName ?? j.serviceId;
  console.log(`${j.status.padEnd(12)} ${svc}  ${j.id}`);
}

// Filter to failed jobs using a JSONPath expression
for await (const j of client.jobs.list({
  contentPath: '$.status == "failed"',
})) {
  console.log("failed:", j.id);
}

// Single-page fetch
const page = await client.jobs.listPage({ limit: 10 });
console.log(page.items.map(j => j.id));

    Accessing Job Outputs¶

    Inline Result Payload¶

    For services that return small JSON results directly:

    const job = await client.jobs.get(jobId);

if (job.resultContent) {
  console.log("Result:", JSON.stringify(job.resultContent, null, 2));
}

    Large Results (Artifact URN)¶

    Large results are stored as DataFabric artifacts:

    if (job.resultContentUrn) {
  const bytes = await client.artifacts.download(job.resultContentUrn);
  console.log("Downloaded", bytes.byteLength, "bytes");
}

    Products (Output Artifact List)¶

    Many services produce multiple output artifacts listed in job.products.items:

    for (const product of job.products?.items ?? []) {
  console.log(product.id, product.mimeType, product.size);

  const bytes = await client.artifacts.download(product.id);
  // ...
}

    DataFabric Aspects¶

    Every job writes aspects into the DataFabric. Fetch all three in one call:

    const aspects = await client.jobs.getAspects(jobId);

// Primary metadata (always present)
console.log(aspects.job?.status, aspects.job?.requestedAt);

// Execution-phase detail (present during / after execution)
console.log(aspects.result?.phase);

// Nextflow-specific results (only for Nextflow jobs)
if (aspects.nextflow) {
  console.log("Pipeline status:", aspects.nextflow.status);
  console.log("Log artifact:  ", aspects.nextflow.logUrn);
  console.log("Process results:", aspects.nextflow.results);
}

    Real-Time Events (SSE) (Node.js only)¶

    Stream progress events while a job is running:

    // Resolve serviceId if you only have the job URN
const serviceId = await client.jobs.resolveServiceId(jobId);

for await (const event of client.jobs.events(serviceId, jobId)) {
  const ts = event.timestamp ?? new Date().toISOString();
  console.log(`[${ts}] ${event.type ?? "unknown"}`);
  if (event.data) console.log("  ", JSON.stringify(event.data));
}

    Resume a dropped stream with lastEventId:

    for await (const event of client.jobs.events(serviceId, jobId, {
  lastEventId: lastSeenEventId,
})) {
  // ...
}

    Error Handling¶

    import { TimeoutError, NotFoundError, IvcapError } from "@ivcap/client";

try {
  const job = await client.jobs.createAndWait(serviceId, req, {
    timeout: 60_000,
  });

  switch (job.status) {
    case "succeeded":
      console.log("✓ succeeded");
      break;
    case "failed":
      console.error("✗ failed:", job.errorMessage);
      break;
    case "error":
      console.error("✗ platform error — contact support, job:", job.id);
      break;
  }
} catch (err) {
  if (err instanceof TimeoutError) {
    console.error("Job did not complete within the time limit");
  } else if (err instanceof NotFoundError) {
    console.error("Service not found:", serviceId);
  } else if (err instanceof IvcapError) {
    console.error(`IVCAP error [${err.statusCode}]: ${err.message}`);
  } else {
    throw err;
  }
}
